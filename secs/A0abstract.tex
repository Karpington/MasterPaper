Large language models can use software tools, but successful calls do not necessarily produce a correct task outcome.
This paper compares three orchestration variants for a scheduling assistant based on the Model Context Protocol (MCP): individual tools with a planner, bundled backend tools with a planner, and individual tools without a separate planner.
We tested three models on two scenarios and assessed technical success, correct tool use and outcome correctness separately.
We also measured response time and model-call cost.
Claude Haiku 4.5 without a separate planner produced correct outcomes in all regular runs.
Backend orchestration was faster and cheaper for this model, but produced fewer correct outcomes.
The main contribution is an empirical comparison showing why correct outcomes must be assessed alongside time and cost.
All variants use application-side validation and require user confirmation before booking.
The findings support prototype selection for this task, but do not establish an independent model ranking or production readiness.
